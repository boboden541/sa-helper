# Языковой пресет: MSSQL SSDT (проект базы данных, data-only)

> Слой досье 5 (v2 §5). Система без исполняемого кода: репозиторий содержит DDL-структуру базы MSSQL (таблицы, вьюхи, процедуры, права). Сборка и тесты не применимы — гейты `SKIPPED (data-only)` (v2 §17 п. 7).

## Границы

- Задачи по такой системе — только **DDL/схема**: таблицы, колонки, вьюхи, права, репликационные скрипты (`uatdb_repl_*`).
- DDL-правило v2 §7 п. 6 жёстче для БД: только **расширительные** изменения (`ADD COLUMN NULLABLE`, `CREATE TABLE`, `CREATE VIEW`), никаких DROP/ALTER-TYPE у живых объектов без явной задачи в требованиях.
- Каждое изменение схемы — отдельным скриптом/файлом с заголовком-комментарием (ссылка на FR-ID), по конвенции репозитория.

## Проверки вместо тестов

- Синтаксический/структурный контроль DDL не автоматизируется в пилоте: контроль — ревью (`/impl-review` рубрика п. 4 «обратная совместимость») и сверка с требованиями.
- Задача-«контракт» для схемы: фиксация затронутых объектов и колонок в карточке задачи (T1 при мульти-системной задаче) — потребители схемы (репликационные скрипты) проверяются на согласованность ревью.

## Ловушки

- В репо могут быть сгенерированные артефакты (`.jira`, XML-проектные файлы) — не редактировать вручную.
- Кроссплатформенность: SQL-файлы — UTF-8 без BOM, окончания строк не менять массово (blame/дифф).
- Не запускать DDL против живых баз: контейнер MSSQL для проверки — вне базового контура (v2 §17 п. 7), только по явной задаче в требованиях.
