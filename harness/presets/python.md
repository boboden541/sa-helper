# Языковой пресет: Python (pytest)

> Слой досье 5 (v2 §5). Кодер следует пресету поверх общих правил, но Golden Reference репозитория приоритетнее пресета: расхождения решаются в пользу эталона и конвенций репо.

## Исполнение в Docker

- Тесты и линтеры запускаются командой из `workspaces.yaml` — контейнер с примонтированным репозиторием; **не предполагай локальный Python-окружение**.
- Пути в результатах тестов — относительно корня репозитория (volume mount = корень репо): ссылки `файл:строка` из отчётов валидны на хосте.
- Ставить пакеты в контейнер «на месте» нельзя: если тесту нужна зависимость — она должна быть в `requirements-test.txt` репозитория.

## Тесты

- **Имя теста = критерий приёмки:** `test_ac_<N>_<k>_<действие>`, например `test_ac_2_1_returns_200_for_new_order`. Это звено трассируемости FR → AC → тест (v2 §7).
- Каркас: `pytest` + `unittest.mock`/`pytest-mock` (если уже используется в репо). Стиль следуй Golden Reference репо (фикстуры, conftest.py).
- Параметризация: `@pytest.mark.parametrize` для табличных критериев «при X → Y»; каждый параметр — отдельный критерий или ветка критерия.
- Исключения: `with pytest.raises(<Тип>, match="фрагмент"):` — тип обязателен, `match` — на стабильную часть сообщения.
- Структура AAA (Arrange–Act–Assert), один логический assert на критерий.
- Без сети, без реальной БД: зависимости — моки по Golden Reference репо; время — `freezegun`/`monkeypatch` только если уже в конвенциях репо.

## Код

- Type hints обязательны, modern unions `X | None` (репо-конвенция: если репо на старом Python — `Optional[X]` по стилю репо).
- Ошибки: поднимай доменные исключения репо (Golden Reference), не голый `Exception`.
- Логи через логгер репо (Golden Reference), не print.
- Легаси без тестов: первая задача — характеризационные snapshot-тесты текущего поведения (As-Is), фиксируй фактическое поведение, не желаемое.
- Минимальная реализация: ровно на падающие тесты, без «на вырост».
- Изменяешь подпись/поведение соседнего кода — сначала ищи импортёров (ripgrep), прогони их тесты (impact-лестница §7 п. 5).
- Windows Git Bash: в тестах только `pathlib.Path`/`os.path`, никаких жёстких `/`-путей в ассертах.
- Правки только в ветках `harness/*` в worktree; main/develop не трогать.
