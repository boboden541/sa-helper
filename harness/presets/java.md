# Языковой пресет: Java (Maven, JUnit 5)

> Слой досье 5 (v2 §5). Golden Reference репозитория приоритетнее пресета: расхождения решаются в пользу эталона и конвенций репо.

## Исполнение в Docker

- Сборка и тесты — через `docker run` с примонтированным репозиторием (`-w /ws`), образ задаётся в `workspaces.yaml`; **не предполагай локальный JDK/Maven на хосте**.
- Кэш зависимостей: volume для `/root/.m2` — иначе каждый прогон качает половину интернета.
- Surefire-отчёты пишутся в `target/surefire-reports/*.xml` (примонтировано) — `runner.py --junit` парсит их на хосте; ссылки `файл:строка` валидны на хосте.
- Сетевой доступ контейнера — только к зависимостям сборки; живые внешние системы в тестах не используются (см. конвенции репо).

## Тесты

- **Имя теста = критерий приёмки:** `test_ac_<N>_<k>_<действие>` (camelCase: `testAc2_1Returns200ForNewOrder` — по конвенции репо; единообразие важнее формы).
- Каркас: JUnit 5 (`@Test`, `@DisplayName` опционален) + AssertJ (если в конвенциях репо) + Mockito (mock-junit-jupiter).
- Параметризация: `@ParameterizedTest` + `@MethodSource`/`@CsvSource` — табличные критерии «при X → Y».
- Исключения: `assertThatThrownBy(...).isInstanceOf(X.class).hasMessageContaining("...")` (AssertJ) или `assertThrows`.
- Структура AAA; один логический assert на критерий.

## Код

- Изменяешь публичную сигнатуру — сначала импортёры (ripgrep), их тесты (impact-лестница v2 §7 п. 5).
- Минимальная реализация ровно на падающие тесты; DI — как в Golden Reference (конструктор, `@InjectMocks` в тестах).
- Ошибки: доменные исключения репо, не голый `RuntimeException`.
- Легаси без тестов: первая задача — характеризационные тесты As-Is.

## Известные ловушки

- Генерация кода (annotation processors: Lombok/MapStruct) в докер-прогоне требует того же JDK-пакета, что и в CI репо — сверяй с `pom.xml` (maven.compiler.release) и CI-конфигом.
- Windows Git Bash: пути монтирования — `%CD%`-совместимые формы; prefer compose-файл, если репо его имеет.
