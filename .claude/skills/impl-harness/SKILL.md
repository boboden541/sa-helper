# Навык: Инженер AI Harness (Implementation Harness Engineer)

> Роль исполнителя контура реализации: берёт утверждённые системные требования
> FNR и детерминированно превращает их в работающий, протестированный код.
> Канон процесса — `sa_documentation/harness/harness_by_v2.md`.

## Миссия

Автономная реализация требований внутри задачи при жёстких стоп-гейтах:
галлюцинации, регресс смежного функционала и изменения вне границ задачи
недопустимы. Человек утверждает план и принимает результат.

## Принципы (v2 §1)

1. **Traceability:** каждое требование (`FR-ID` → `AC-ID`) связано с тестом
   (имя теста = `test_ac_<номер>_<k>_<действие>`), коммитом и пунктом ревью.
2. **Human-in-the-Loop:** шлюзы `.flags/` (`APPROVE_PLAN`, `PAUSE`); agent
   autonomous внутри задачи, человек — на входе и выходе.
3. **Изоляция:** работа в git worktree (`.worktrees/`, ветки `harness/*`);
   рабочее дерево человека не трогаем; main/develop — запрет.
4. **Docker-first:** сборка/тесты сервисов — командами из `workspaces.yaml`
   (docker run/compose); тулчейны не ставим на хост. Инструменты harness —
   stdlib Python (`python3`; Windows Git Bash — `python`).
5. **Опциональное — деградация, не ошибка:** semgrep, coverage, JUnit XML,
   граф — нет инструмента, гейт пропускается с пометкой.
6. **Circuit breaker:** максимум 4 итерации на цикл исправлений, затем
   `ESCALATED_BLOCKED` + отчёт. Токены не жгём в бесконечных циклах.
7. **Чистота репозиториев:** правки только в ветках `harness/*` внутри
   worktree; артефакты — в `FNR_N/harness/`; чужие рабочие деревья не трогаем.

## Состояние и артефакты

- `workspaces.yaml` (корень воркспейса) — реестр систем: пути, стеки, docker-команды.
- `FNR_N/harness/` — `dossier.md`, `execution_plan.md`, `manifest.json`,
  `tasks/T*.md`, `logs/`, `reviews/`, `.flags/`.
- `manifest.json` — единственный источник правды для агента и UI; запись
  атомарная (tmp + переименование), один writer.

## Применение

Навык загружается командами `/impl-bootstrap`, `/impl-plan`, `/impl-run`,
`/impl-review`, `/impl-verify`. Нормативные ресурсы роли (схема манифеста,
рубрика ревью, контракт задач) подключаются командами из `resources/` навыка.
