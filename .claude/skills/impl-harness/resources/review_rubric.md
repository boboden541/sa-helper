# Ресурс: рубрика ревьюера (v2 §11)

Ревьюер — независимый контекст: он не видит диалог кодера, только материалы задачи
(дифф ветки, карточка, досье, фрагменты СТ). Каждая находка — с `файл:строка`;
находка без указания места недействительна.

## Рубрика (6 осей)

1. **Трассируемость требований:** каждый FR задачи покрыт; каждый AC имеет тест;
   имена тестов соответствуют канону `test_ac_*`; коммит ссылается на `[FNR-<N>/T<k>]`.
2. **Безопасность:** инъекции (SQL/команды/шаблоны), валидация входа (схемы применяются
   к границам), ошибки без утечки стектрейсов наружу, секреты не попали в дифф/логи.
3. **Обратная совместимость:** публичные сигнатуры не ломаются; изменения БД — только
   расширительные (ADD COLUMN NULLABLE, CREATE); потребители изменённого не сломаны
   (impact-срез подтверждён).
4. **Соответствие Golden Reference:** стиль диффа повторяет эталоны из dossier.md
   (DI, обработка ошибок, структура тестов); расхождения — обоснованы или найдены.
5. **NFR:** числовые требования СТ для затронутого кода проверяемы; деградаций
   производительности очевидных путей нет.
6. **Покрытие диффа:** каждый содержательный блок диффа достигается хотя бы одним тестом;
   coverage изменённых файлов ≥ 80% (или `skipped` с пометкой, почему).

## Вердикты

| Вердикт | Когда | Действие |
|---|---|---|
| `APPROVED` | критичных и существенных находок нет; замечания — только nit-уровня | задача `DONE`, worktree удаляется, дифф готов к PR |
| `CHANGES_REQUESTED` | есть существенные находки | возврат в `/impl-run` с дельтой замечаний (нумерованный список); после доработки — повторное ревью |
| `BLOCKED` | задача реализует не то / критерии невыполнимы / требуется решение человека | эскалация: отчёт + STOP контура по задаче |

## Отчёт (reviews/T<k>_review.md)

- Вердикт + таблица находок: `# | Ось рубрики | файл:строка | Существенность (критично/существенно/nit) | Суть | Как чинить`.
- Подтверждённые проверки по каждой из 6 осей (что именно смотрел, что подтверждено).
- Что ревьюер НЕ проверял (границы ревью — например, живые внешние системы).

## Verdict-блок (machine-readable, обязателен в конце отчёта)

Демон конвейера парсит этот блок детерминированно (без LLM) и ведёт петлю
доработки (closure_first / лимит итераций). Формат — ровно такой:

```
## Verdict (machine-readable)
status: APPROVED | CHANGES_REQUESTED
blocking:
- <id|-> | file: <путь:строка> | text: <суть замечания>
advisory:
- ...
previous:
- <id>: resolved | still_blocking
```

Правила:

1. `id` находки опционален: вместо него — `-` (демон вычислит стабильный хеш
   `file|text`). Явные короткие id (`b1`, `b2`…) приветствуются — на них ссылается
   `previous` в следующих итерациях.
2. `previous` — статус находок прошлой итерации: `resolved` (исправлено) или
   `still_blocking` (не исправлено). При первом ревью секция не нужна. Если секции
   нет вовсе, демон сверит id сам по findings в манифесте.
3. Существенность в тексте отчёта; в blocking попадают критичные и существенные,
   в advisory — nit. Блок обязан соответствовать вердикту: CHANGES_REQUESTED ⇔
   blocking непустой; APPROVED ⇔ пустой.
