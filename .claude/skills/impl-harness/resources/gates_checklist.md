# Ресурс: гейты исполнителя (RED-гейт, circuit breaker, impact-лестница)

## 1. RED-гейт (v2 §7)

Тесты acceptance-критериев обязаны упасть **до** кода. Правила:

1. Тесты пишутся до реализации, по карточке задачи: имена `test_ac_<номер>_<k>_<действие>`.
2. Прогон: `runner.py --mode test` (команда из `workspaces.yaml`, `--log logs/T<k>_red.log`).
3. **Фиктивный тест** — тест, который проходит без реализации. Признаки: проверяет только
   существующий код/типы, тавтологии (`assert True`, проверка констант), тестирует не то,
   что требует критерий.
4. Тесты прошли без кода → тесты бракуются и переписываются (это не итерация circuit breaker),
   статус остаётся dummy-proofing; только честный RED переводит задачу в `TDD_RED`.

## 2. Circuit breaker (= 4)

`iteration_count` +1 за каждый цикл «код упал → исправил → прогнал» ПОСЛЕ честного RED.

- > 4 → `ESCALATED_BLOCKED` + `logs/T<k>_failure_report.md`: что делал, что падает (с
  `файл:строка`), гипотезы, что нужно человеку. Токены не жгутся в бесконечных циклах.
- Пауза: `.flags/PAUSE` проверяется **перед каждой итерацией**; появился → стоп, манифест в
  текущем состоянии, снятие паузы — человеком (`rm .flags/PAUSE`), продолжение той же командой.

## 3. Impact-лестница (защита от регресса, v2 §7 п. 5)

После GREEN, перед коммитом:

1. Изменённые файлы задачи → `ripgrep` по импортам/вызовам (или `graph_impact`, если граф
   доступен): кто потребляет изменённое.
2. Прогнать тесты потребляющих модулей (суженный скоуп: их каталоги/файлы pytest-а или
   `-Dtest=` в Maven). Если потребляющий модуль без тестов — отметить в резюме.
3. При регрессе — вернуть задачу в GREEN-цикл (итерация +1).
4. Полный сьют репо — зона `/impl-verify` (не в run).

## 4. Coverage-гейт (опциональный, v2 §17 п. 1)

- Инструмент есть (pytest-cov/jacoco): дельта по изменённым файлам ≥ 80% строк.
- Нет инструмента → `gates.coverage = "skipped"` — **не блокирует**.

## 5. Коммиты

- Формат: `[FNR-<N>/T<k>] <feat|test|docs|chore>: <кратко>`; только в ветке задачи
  (enforcement-хук pre-commit), push в main/develop — запрещён (хук + permissions).
- Worktree живёт до ревью; удаляет `/impl-review` (APPROVED) или человек.
