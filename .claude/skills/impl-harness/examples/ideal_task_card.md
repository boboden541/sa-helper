# Пример: карточка задачи (tasks/T<k>.md)

> Шаблон карточки, которую генерирует `/impl-plan`. Карточка — полный рабочий контракт задачи:
> кодер работает только по ней + досье, в СТ ходит по ссылкам. Заполняется без отсебятины:
> каждое поле выводимо из СТ или dossier.

```markdown
# T<k>: <название из СТ>

| Поле | Значение |
|------|----------|
| FR | FR-<номер задачи> (см. `../../<system_requirements>.md`) |
| Система | <имя из workspaces.yaml> |
| Фаза | regular \| contract \| producer \| consumer \| characterization |
| Ветка | harness/FNR-<N>-<slug>-t<k> |
| Worktree | .worktrees/FNR-<N>-t<k> |
| Зависимости | нет / T<j> (<почему>) |
| Пресет | harness/presets/<стек>.md |

## Что сделать

<Пересказ требований задачи своими словами — 3-7 предложений из «Описание доработок» СТ.
Правила от подлежащего, ветвления — явно. Ничего сверх СТ.>

## Критерии приёмки

| AC | Условие (из СТ дословно по смыслу) | Тест |
|----|------------------------------------|------|
| AC-<номер>.1 | <проверяемое условие> | test_ac_<номер>_1_<действие> |
| AC-<номер>.2 | <проверяемое условие> | test_ac_<номер>_2_<действие> |

## Golden Reference (из dossier)

- <похожая реализация в этом же репо>: `<файл:строка>` — что взять: <DI, валидация, ошибки>.
- Конвенции репо: <гайдлайн/факты из dossier>.

## Границы

- **Не входит:** <смежные задачи и явно вне границ — из СТ>.
- **Не трогать:** <файлы/модули вне скоупа, которые легко задеть>.

## Гейты

build: <команда из workspaces.yaml> · test: <команда> · coverage: <инструмент есть/нет>
```

## Правила заполнения

1. **AC — из СТ, не выдуманные.** Если критерий СТ не проверяем автотестом (визуальный, ручной) —
   пометь `ручная проверка` в колонке «Тест» и зафиксируй в manifest (`test: null`).
2. **Одна карточка — одна система.** Сквозные изменения двух репо — две задачи + контрактная
   фаза, если меняется взаимодействие (`resources/contract_first.md`).
3. **«Не трогать» обязательно** для задач в общих модулях: перечень берётся из impact-среза dossier.
4. Карточка самодостаточна: кодер не должен открывать СТ, чтобы понять, что делать, — только
   чтобы проверить точность пересказа.
