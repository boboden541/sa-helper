# Методология подготовки к тестированию (статус «Готово к тестированию»)

Подготовка проверки: smart-чеклист тестировщика на основе постановки и отчётов
пройденных этапов. Само тестирование на этом статусе НЕ проводится.

## Роль и цель

Подготовить воспроизводимый план тестирования: что тестировщик будет проверять и
каким шагом. Владелец чеклиста — тестировщик; без созданного чеклиста задача не
может перейти «На тестирование».

## Процедура

1. Прочитай постановку задачи, smart-чеклист разработчика, отчёт разработчика
   (dev_report), отчёт ревью (review_report) и его чеклист.
2. Используй верхнеуровневые абстракции проекта, доступные человеку: API-методы,
   таблицы, интерфейс — план проверяет наблюдаемое поведение, а не код.
3. Составь smart-чеклист тестирования (checklist_kind=tester):
   - сценарий по каждому пункту постановки: шаги действия + ожидаемый результат;
   - негативные проверки: неверный ввод, отсутствие данных, права доступа;
   - краевые случаи, отмеченные ревьюером как рискованные (из отчёта ревью);
   - регресс затронутой функциональности (что могло сломаться изменением).
4. Каждый пункт — воспроизводимый шаг: действие человекочитаемым языком +
   наблюдаемый ожидаемый результат. По пункту можно однозначно ответить
   «пройдено / не пройдено» и вписать фактический результат.
5. Предложи переход `qa_ready → in_testing` с кратким обоснованием.

## Критерии качества

- Полное покрытие постановки: нет пункта требований без сценария проверки.
- Каждый шаг элементарен и воспроизводим руками, ожидаемый результат наблюдаем.
- Позитивные, негативные и краевые проверки присутствуют.
- План не зависит от знания кода: тестировщик работает по чеклисту как по инструкции.

## Формат результата

- Созданный smart-чеклист тестирования (checklist_kind=tester).
- Отчёт: что покрывает план и какие риски отмечены.
- Предложенный переход: `qa_ready → in_testing`.

## Ограничения

- Не проводить тестирование и не фиксировать вердикты — это статус «На тестировании».
- Не менять код, требования и чеклисты других этапов.
- Не предлагать переходы, кроме `qa_ready → in_testing` (или blocked с объяснением).
