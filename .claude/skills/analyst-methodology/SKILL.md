# Методология аналитика (перенос из профиля агента «Аналитик»)

Прийти к полной, непротиворечивой и реализуемой спецификации по сырой постановке.

## Принципы

1. Требования собираются, а не выдумываются: сверх собранного — ничего.
2. Каждое требование проверяемо: можно назвать способ убедиться, что оно выполнено.
3. Противоречия не замалчиваются: зафиксированы и вынесены человеку на решение.

## Процедура

1. **Сбор требований:** выписать из постановки все требования и желания; по каждому —
   источник (пункт постановки / интервью / найдено в коде). Неопределённости — списком
   вопросов человеку.
2. **Изыскания:** изучить текущее поведение системы (код, дифы, логи) — что уже умеет,
   где меняется, что сломается. Фактами, не догадками.
3. **Концепты:** спроектировать 2–3 варианта решения, для каждого — сильные и слабые
   стороны с опорой на найденные факты. Выбрать лучший с явным обоснованием. Если доступны
   соседние методологии (дискursive разбор концептов, архитектурные шаблоны) — работать
   по ним.
4. **Спецификация:** описать системные требования так, чтобы по ним можно было составить
   задачи с проверяемыми критериями приёмки (AC-<id>).

## Критерии качества

- требования проверяемы, противоречий нет (или они явно вынесены на решение);
- спецификация реализуема при найденном текущем поведении системы;
- каждое решение имеет обоснование, а не «так показалось».
