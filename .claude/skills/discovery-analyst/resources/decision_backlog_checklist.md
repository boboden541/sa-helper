# Чек-лист валидации 01_decision_backlog.md

## 1. Развилка как развилка, а не решение
- [ ] Каждая карточка — вопрос, который **нельзя закрыть чтением кода** (решение за человеком).
- [ ] [CRITICAL] Нет проектируемых решений в бизнес-полях («нужно сделать…», «лучше переписать…»).
- [ ] Варианты сформулированы как **бизнес-выбор**, не как технические реализации.

## 2. Два слоя языка
- [ ] [CRITICAL] В бизнес-полях (Вопрос/Почему важно/Что сломается/Варианты/Рекомендация/Цена ошибки) нет идентификаторов, классов, флагов, переменных, тикетов.
- [ ] Технические доказательства — только в поле «Доказательство (для аналитика)».
- [ ] Тест «понял бы руководитель без кода?» проходит для каждого бизнес-поля.

## 3. Доказательная база
- [ ] У каждой карточки есть поле «Доказательство» с `файл:строка` ИЛИ явная метка `[NEEDS_INVESTIGATION]`.
- [ ] [CRITICAL] Развилка без доказательства и без `[NEEDS_INVESTIGATION]` — 🔴.

## 4. Форсинг-функция (полнота карточки)
- [ ] Есть «Вопрос (для кого)» с указанием адресата (руководство/бизнес/архитектура/безопасность/юристы/…).
- [ ] Есть «Почему важно» и «Что сломается» (разные — одно про зависимость, другое про последствия).
- [ ] Есть ≥2 вариантов и «Цена ошибки "угадать"».

## 5. Ранжирование и статусы
- [ ] Заполнена «Сводка бэклога» (ID / Развилка / Статус / Кто отвечает / Блокер?).
- [ ] Статусы корректны: 🔴 открыт · 🟡 частично · 🟢 решён.
- [ ] Блокеры (без которых `/fnr-concept` даст вслепую) помечены.

## 6. Связь с досье
- [ ] Каждая `[NEEDS_INVESTIGATION]` имеет соответствие в `04_action_points.md`.
- [ ] Белые пятна из `00_context.md` отражены как карточки или action points.

## 7. Полнота спектра (карта покрытия)
- [ ] В конце бэклога есть «Карта покрытия» по 12 измерениям (`resources/question_coverage.md`).
- [ ] [CRITICAL] Каждое измерение закрыто карточкой ИЛИ явным «не применимо» с причиной — молчаливый пропуск запрещён.
- [ ] Для задач замены/переезда есть карточка с вариантом «не переносить / переосмыслить» (взгляд «снаружи»).
- [ ] Вопросы пользовательских сценариев сформулированы от задач пользователя (user story), а не от текущих экранов.
- [ ] Баланс адресатов: нет перекоса больше 2/3 вопросов на одну роль (бизнес/техлиды/данные/безопасность/эксплуатация).

---

## Hard Gates (🔴)

1. **No Business-Tech Gate:** техническая абстракция в бизнес-поле карточки — 🔴.
2. **Evidence Gate:** карточка без доказательства и без `[NEEDS_INVESTIGATION]` — 🔴.
3. **Solution Gate:** карточка содержит проектируемое решение вместо развилки — 🔴.
4. **Forcing Gate:** отсутствует «Вопрос (для кого)» или «Что сломается» — 🔴.
5. **Path Gate:** абсолютные пути в ссылках — 🔴.
6. **Coverage Gate:** измерение карты покрытия пропущено молча (нет ни карточки, ни «не применимо» с причиной) — 🔴.
