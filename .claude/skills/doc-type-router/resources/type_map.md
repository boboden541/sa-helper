# Карта типов документации (type map)

> **Единственный источник истины** для соответствия «тип документа ↔ папка ↔ признаки ↔ префикс файла». Редактируется пользователем напрямую: чтобы завести новый тип или уточнить признаки — добавь/поменяй строку в таблице. Команды (`/context-gen`, `/create-doc`, `/validate-doc`) сверяются с этой таблицей, а не с собственными копиями.

## Реверс-инжиниринг (документы раскладываются по `sa_documentation/<сервис>-docs/<мнемоника>/`)

| Тип документации | Мнемоника (папка) | Признаки определения | Где определяется | Префикс файла |
|---|---|---|---|---|
| API-документ (эндпоинт) | `api` | Описание ОДНОГО REST/GraphQL/gRPC-эндпоинта: контракт вход/выход, маппинг полей на БД, диаграммы, якоря истины | `/open-api` (машиночитаемая спека), `/create-doc` (тип задачи API) | `api_` |
| Интеграция | `integrations` | Взаимодействие с одним внешним сервисом/партнёром (исходящее или входящее): партнёр, протокол, физический эндпоинт, передаваемые данные, маппинг «наш ↔ партнёр», обработка ошибок партнёра | `/create-doc` (тип задачи Integration) | `integration_` |
| Экран (UI) | `screens` | Одна страница/экран UI: карта вызываемых API-методов, маршруты, фронтенд-логика, сквозной флоу загрузки | `/create-doc` (тип задачи Screen) | `screen_` |
| Архитектура | `architecture` | Компоненты и слои сервиса, C4-диаграммы, границы систем, общая структура решения | `/arch-gen` (C4 L3), `/create-doc` (тип задачи Architecture) | `architecture_` |
| ERD | `erd` | Структура БД/схемы: таблицы, колонки, типы, связи, кардинальности, ограничения (источник — DDL/миграции/ORM) | `/create-doc` (тип задачи ERD, скилл `db_archeologist`) | `erd_` |
| Data trace | `data_trace` | Путь данных от входа до хранилища: lineage полей, трансформации по слоям, точка назначения `[DB].[SCHEMA].[TABLE].[COLUMN]` | `/data-trace` | `data_trace_` |
| Процесс | `processes` | Сквозной бизнес-процесс через компоненты/сервисы: участники, шаги, ветвления, альтернативные сценарии | `/create-doc` (тип задачи Process) | `process_` |
| OpenAPI-спека | `api/openapi` | Машиночитаемый контракт API (YAML, OpenAPI 3.0.3); доменный файл — один на домен | `/open-api` | `<domain>.yaml` |

|---|---|---|---|---|
| Постановка задачи | `FNR` | Структурированное описание проблемы на основе анализа кодовой базы | `/fnr-new-task` | `task.md` |
| Концепт решения | `FNR` | Варианты решения проблемы, дебаты и вердикт | `/fnr-concept`, `/fnr-debate` | `concept.md` |

| Discovery-досье | `FNR` | Контекст, Decision Backlog, ответы, бриф, action points по неизвестным | `/discovery`, `/discovery-answer`, `/discovery-brief` | `00_…`–`04_…` |
| PRD-grooming | `prd` | Разбор и подготовка PRD: уточнение требований, открытые вопросы | `/prd-grooming` | `<slug>-grooming.md` |

## Правила пользования

1. Тип определяется по признакам, а не по имени вызванной команды: `/create-doc` порождает документы семи реверс-типов.
2. Спорный случай (например, «описать, как сервис ходит в другой за данными» — это интеграция или data trace?): интеграция описывает **контракт с партнёром** (что и как передаётся), data trace — **путь поля внутри нашего сервиса** до хранилища. Если по формулировке не решить — спроси пользователя.
3. Новая строка таблицы = новый тип: заполни все колонки; мнемоника — kebab/snake_case латиницей; после добавления типа заведи для него эталонный шаблон в соответствующем скилле (по канону «структура только из эталонного шаблона»).
