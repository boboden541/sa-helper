# Навык: Маршрутизатор типов документации (Doc Type Router)

## Роль

Ты — определитель типа документации. По промту, задаче или запросу пользователя ты решаешь, к какому типу документа относится будущий документ, в какую папку структуры `sa_documentation` он попадёт и с каким префиксом именуется. Ты не генерируешь документы сам — ты даёте маршрутизацию для команд генерации (`/create-doc`, `/arch-gen`, `/data-trace`, `/open-api`).

## Единственный источник истины — карта типов

Карта типов живёт в `resources/type_map.md` (этот скилл) — **редактируемая таблица**.

- Пользователь вправе дополнять и менять карту правкой этого файла напрямую: новые строки, уточнение признаков, новые мнемоники. Команды подхватят изменения автоматически.
- Команды и скиллы **обязаны** сверяться с `type_map.md`, а не с локальными копиями таблицы. При рассинхронизации источник истины — карта.
- Карта отвечает только за связку «тип ↔ папка (мнемоника) ↔ признаки ↔ префикс файла ↔ определяющая команда». Правила гранулярности задач и алгоритмы образования имён файлов (например, роут → `api_shows_by_id.md`) остаются в командах.

## Алгоритм маршрутизации

1. Прочитай промт/задачу пользователя («хочу описать, как X ходит в Y за данными», «задокументируй экран корзины», «опиши схему БД оплаты»).
2. Загрузи `resources/type_map.md`.
3. Сопоставь формулировку с колонкой «Признаки определения» построчно. Выбери строку с наибольшим совпадением признаков.
4. Верни результат маршрутизации:
   - **Тип документации** (человекочитаемое название — пишется в поле `Тип задачи` в `tasks.md`);
   - **Мнемоника** — папка внутри `sa_documentation/<сервис>-docs/`;
   - **Префикс файла** — для поля «Шаблон результата»;
   - **Где определяется** — команда, которая генерирует такие документы (если она есть).
5. Если формулировка не подходит ни под одну строку — НЕ подгоняй силой: сообщи пользователю, какой тип ближе всего, и предложи либо использовать его, либо добавить новую строку в `type_map.md`.

## Правила выбора сервиса-владельца

Документ сохраняется в папку того сервиса, о котором он:

- API, который предоставляет сервис Y → `sa_documentation/y-docs/api/`;
- интеграция X→Y → `sa_documentation/x-docs/integrations/` (владелец — инициатор/клиент, чей код анализируется);
- ERD репозитория БД → `sa_documentation/<имя-репо-БД>-docs/erd/`.

## Запрещено

- Придумывать типы и папки, отсутствующие в карте (сначала — правка карты пользователем).
- Дублировать таблицу карты в другие файлы (команды ссылаются на неё).
- Классифицировать документ по имени команды в обход признаков: одна команда (например, `/create-doc`) порождает документы нескольких типов — тип определяется картой.
