# Чек-лист груминга PRD

## 1. Понятность (Clarity)

- [ ] По каждому требованию можно сформулировать хотя бы один проверяемый критерий приёмки
- [ ] Нет «резиновых» формулировок («наравне», «непропорционально», «где-то», «обычно») без раскрытия
- [ ] Все термины и аббревиатуры определены (в PRD или ссылкой на глоссарий)
- [ ] Требование атомарно — одно требование не смешивает 3–4 разных смысла

## 2. Валидность (Validity)

- [ ] Каждое требование трассируется на бизнес-цель и/или пользовательский сценарий
- [ ] Метрики измеримы: есть базовое значение, цель и срок
- [ ] Определён scope: что входит / что не входит / что MVP
- [ ] Покрыты негативные сценарии (ошибки, пустые состояния, недоступность)
- [ ] Критерии приёмки покрывают не только «счастливый путь»

## 3. Реализуемость (Feasibility)

- [ ] Под каждое поле/фильтр/признак определён источник данных
- [ ] [CRITICAL] Нет требований, опирающихся на данные, которых нет в источнике
- [ ] Подтверждено (или вынесено в вопрос), что текущая платформа поддерживает описанное поведение
- [ ] Внешние зависимости перечислены и имеют владельца
- [ ] Описано поведение при деградации/недоступности внешних систем
- [ ] Где система есть в кодовой базе — реализуемость подтверждена кодом/графом (файл:строка)

## 4. Непротиворечивость (Consistency)

- [ ] [CRITICAL] Разделы PRD не противоречат друг другу
- [ ] Текст PRD согласован с макетами (если макеты приложены)
- [ ] Все перекрёстные ссылки («см. пункт N») ведут на существующие разделы и корректны

## 5. Качество отчёта

- [ ] У каждой находки указана ось (понятность / валидность / реализуемость / непротиворечивость)
- [ ] У каждой находки проставлен severity (🔴 / 🟠 / 🟡)
- [ ] Каждая находка имеет опору: ссылка на раздел PRD / код (файл:строка) / макет — либо помечена как вопрос
- [ ] У каждого вопроса указан адресат (роль/владелец)
- [ ] Системные наблюдения об уровне документа вынесены в резюме, а не размножены построчно
- [ ] Все ссылки на файлы кода — относительные (нет абсолютных путей)

---

## Hard Gates (🔴)

1. **Verdict Gate:** Вердикт ✅, но в находках есть 🔴 — противоречие, недопустимо.
2. **Evidence Gate:** Находка сформулирована как факт, но без опоры (раздел/код/макет) и не помечена как вопрос — 🔴.
3. **Owner Gate:** Вопрос без адресата — 🔴.
4. **Axis Gate:** Находка без классификации по оси — 🔴.
5. **Path Gate:** Абсолютные пути в ссылках на код — 🔴.
