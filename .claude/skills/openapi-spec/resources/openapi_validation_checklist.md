# Чек-лист валидации OpenAPI-спецификации

Проверяется перед завершением команды `/open-api`. Hard Gates (🔴) обязательны — при нарушении спека не считается готовой.

## 1. Синтаксис и структура

- [ ] Документ — валидный YAML (парсится без ошибок).
- [ ] Указан `openapi: 3.0.3` (или явно согласованная версия).
- [ ] Присутствуют корневые секции `info` (с `title`, `version`), `paths`.
- [ ] [CRITICAL] 🔴 **Lint Gate:** внешний валидатор (`npx @redocly/cli@latest lint --extends minimal <file>.yaml` либо `openapi-spec-validator`) вернул **0 errors** (warnings допустимы). Набор `minimal` = структурная конформность, как у плагина IDE.

## 2. Совместимость с плагином «OpenAPI (Swagger) Editor»

- [ ] [CRITICAL] 🔴 Каждый `type` — **одиночная строка** из `{array, boolean, integer, number, object, string}`. Нет union-типов `type: [..., "null"]` (они ломают рендер плагина).
- [ ] Обнуляемость выражена `nullable: true` рядом с `type`, а не union-типом.
- [ ] `exclusiveMinimum`/`exclusiveMaximum` (если есть) — булевы, не числа.
- [ ] Каждый `$ref` указывает на существующую схему в `components/schemas` (нет висячих ссылок).
- [ ] Каждый `type: array` имеет `items`.
- [ ] Каждый `type: object` для известного DTO имеет `properties`.

## 3. Полнота схем (главное требование заказчика)

- [ ] Описаны схемы и запроса (path/query/header-параметры, `requestBody` для методов с телом), и ответа.
- [ ] Для каждого поля заявлен `type` (+ `format`, где применимо).
- [ ] Обязательные поля перечислены в `required` родительского объекта.
- [ ] Где код задаёт ограничения — присутствуют `pattern`, `minLength`/`maxLength`, `minimum`/`maximum`, `enum`.
- [ ] У полей есть `example` (из кода/фикстур), где значение известно.
- [ ] Указан хотя бы один успешный ответ (`2xx`); ошибки (`4xx`/`5xx`) добавлены, если явно обрабатываются в коде.

## 4. Достоверность (без фантазий)

- [ ] [CRITICAL] 🔴 **No Hallucination Gate:** в спеке нет `pattern`/`min*`/`max*`/`enum`/`example`, которых нет в коде.
- [ ] Поля/ограничения, не подтверждённые кодом, помечены `[NEEDS_INVESTIGATION]` в `description`, а не выдуманы.
- [ ] Имена схем совпадают с именами DTO/классов из кода.
- [ ] Найдено ≥2 из 3 якорей истины (Routing / Contract / Model); недостающее отражено как `[NEEDS_INVESTIGATION]`.

## 5. Именование и размещение

- [ ] Имя файла выведено из path по алгоритму нормализации (`SKILL.md`, Этап 2); расширение `.yaml`.
- [ ] Файл лежит в `sa_documentation/<сервис>-docs/api/openapi/` (машиночитаемая часть категории `api` сервиса).
- [ ] В ссылках на код (`x-source`/`description`) нет абсолютных путей.

---

## Hard Gates (🔴)

1. **Lint Gate:** внешний валидатор вернул ошибки (errors > 0) — 🔴.
2. **Type Gate:** хотя бы один `type` не одиночная строка (union-тип 3.1) — 🔴 (плагин не отрендерит).
3. **Ref Gate:** висячий `$ref` / `array` без `items` — 🔴.
4. **No Hallucination Gate:** выдуманное ограничение или `example`, не подтверждённые кодом — 🔴.
5. **Completeness Gate:** отсутствует схема запроса (для метода с телом) или ответа — 🔴.
