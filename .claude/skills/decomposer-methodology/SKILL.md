# Методология декомпозиции (перенос из /impl-plan + /impl-handoff)

Превращение утверждённой постановки (СТ / история) в исполнимый план: досье, DAG задач,
карточки — без выдуманных требований.

## Шлюз готовности входа

План строится только из постановки и кода. Проверь вход:
1. Работы распознаваемы как отдельные задачи (есть принятый канон задач/разделов).
2. У каждой задачи проверяемые критерии приёмки (AC-<id>, «проверяемо тестом»);
   формулировки «согласовать», «по согласованию» без механизма проверки — пробел.
3. При 2+ системах есть раздел о затронутых системах и контрактах.

Пробелы → gap-отчёт (пробел → где в постановке → что дописать) и остановка: статус
blocked / вопросы человеку. Никаких досье, плана и задач, пока вход не поправит человек.

## Досье

Собери контекст исполнения:
1. **Доменный срез:** по каждой затронутой системе 4–7 файлов, непосредственно
   относящихся к работе (поиск по коду/графу); у каждого файла — роль и «что смотреть».
2. **Golden Reference:** в каждом репозитории найди завершённый аналог реализуемого
   (соседний эндпоинт/сервис/процедура), зафиксируй файл:строка для DI, валидаций,
   ошибок, тестов. Исполнитель пишет «по образцу», а не по вкусу.
3. **Конвенции:** гайдлайны репозитория; в репо без тестов первая задача —
   характеризационная.
4. **Контракты:** что связывает системы, кто владелец, где фиксируется. Интерфейсы не
   меняются — «не применимо».

## Декомпозиция и DAG

1. Атомарные задачи: одна карточка = одна система = проверяемый результат.
2. Фазы: контрактная задача — первой (только спецификация взаимодействия, без
   бизнес-логики); characterization — первой в репо без тестов; producers/consumers —
   после контракта.
3. Зависимости — явный DAG; циклы недопустимы.
4. Карточка задачи: полная постановка «контекст → что сделать → критерии», AC с
   ожидаемыми именами тестов, границы (что НЕ входит), ссылки Golden Reference. Человек
   должен понять работу по одному описанию.

## Шлюз утверждения

Сведи план человеку: задачи кратко, DAG, объём, риски. План ждёт утверждения человека —
сам исполнение не начинай и историю в работу не переводи: это делает конвейер после
одобрения.
