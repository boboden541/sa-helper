# Чек-лист самопроверки документа ПСИ

Пройди по пунктам перед сдачей документа. 🔴 — блокер, документ не сдаётся, пока не устранено.

## Структура

- [ ] Есть заголовок «Процедура приёмо-сдаточных испытаний (ПСИ): <функционал> (<код FNR/истории>)» — 🔴
- [ ] Есть блок «Назначение»: для кого документ, как им пользоваться, что он самодостаточен — 🔴
- [ ] Указаны дата документа и номер версии
- [ ] Есть раздел «Что реализовано (простыми словами)»: как было → как стало, без внутренней «техники»
- [ ] Есть «Словарик терминов» — таблица «Термин | Что это (для читателя вне IT)»
- [ ] Есть «Правила проведения ПСИ»: пара «Действие → Ожидаемый результат», порядок выполнения, что делать при расхождении
- [ ] Пункты сгруппированы в разделы по контурам/группам (Г1…Гn)
- [ ] Есть раздел «Замечания по итогам прогона» (на первом прогоне — «Пилотный прогон не проводился»)

## Пункты

- [ ] Каждый пункт — «Действие» (что конкретно сделать) + «Ожидаемый результат» (что увидеть) — 🔴
- [ ] Действие воспроизводимо без помощи инженера: команды приведены целиком, копируются как есть — 🔴
- [ ] Ожидаемый результат наблюдаем (на экране/в выводе), не «внутреннее состояние»
- [ ] У каждого пункта есть «Если расхождение»: где искать причину и когда ставить ✗
- [ ] Негативные проверки присутствуют (отказ без прав доступа, битое тело, повторы/дубли)
- [ ] NFR-пункты помечены advisory, если стенд демонстрационный

## Язык

- [ ] Документ читает человек без «техники»: жаргон раскрыт, термины — в словарике — 🔴
- [ ] В ожидаемых результатах нет имён таблиц/классов/кодов ответов, если это не сам предмет проверки
- [ ] Документ не приукрашивает: ожидания взяты из постановки, не «улучшены»
