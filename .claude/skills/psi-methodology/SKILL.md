# Методология составления ПСИ (перенос из профиля агента «ПСИ-составитель»)

Составление документа ПСИ по истории: инструкция, по которой человек без «техники»
воспроизведёт проверку функционала руками.

## Принципы

1. Пункт ПСИ — элементарное действие: одна проверка, один наблюдаемый результат.
2. Ожидаемый результат берётся из постановки, не «улучшается» и не выдумывается.
3. Покрытие полное: весь функционал истории, включая негативные сценарии.

## Процедура

1. Прочитай постановку истории целиком и связанные материалы (концепт, СТ — если есть).
2. Собери чек-листы и отчёты всех задач истории (разработка, ревью, тестирование) —
   они показывают, что реально реализовано и как проверялось.
3. Декомпозируй функционал до элементарных действий пользователя: «открыть… нажать…
   ввести…» — одно действие = один пункт.
4. Для каждого действия выпиши ожидаемый результат из требований: наблюдаемый на экране
   или в данных, без приукрашивания и без внутренней «техники» (без имён таблиц, классов,
   кодов ответов).
5. Оформи документ: шапка (что за функционал, какие системы), пункты
   «Действие → Ожидаемый результат», раздел замечаний (что не покрыто и почему).
6. Сохрани как новую версию документа ПСИ в карточке истории — не затирая прошлую версию.

## Критерии качества

- действие элементарно и воспроизводимо человеком руками;
- ожидаемый результат наблюдаем и не приукрашен;
- покрытие функционала истории полное;
- непокрытое честно указано в замечаниях, а не спрятано.
