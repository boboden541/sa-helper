# Методология ревью (перенос из команды /impl-review)

Независимое ревью задачи агентом-критиком в конвейере AI-Harness.

## Независимость — главное

Ревью строится только на материалах задачи: дифф ветки, карточка и её чек-листы, связанная
постановка/история, сводки гейтов. Диалог разработчика и его объяснения материалом не
являются — суди по коду и артефактам. Не додумывай контекст: данных не хватает, чтобы
проверить направление, — это находка, а не повод промолчать.

## Рубрика (6 осей)

Каждая находка: файл:строка + существенность (критично / существенно / nit) + как чинить.

1. **Трассируемость:** каждое изменение связывается с пунктом постановки; изменения вне
   скоупа задачи — находка.
2. **Корректность:** логика, обработка ошибок и краевых случаев, утечки ресурсов, гонки.
3. **Миграции и схема (для data-only — главная ось):** расширительность и обратная
   совместимость, идемпотентность, разрушающие операции без явной необходимости.
4. **Тесты:** проверяют acceptance-критерии; нет фиктивных (прошли бы на пустом коде),
   отключённых и закомментированных проверок.
5. **Конвенции репозитория:** стиль и структура по гайдлайнам и Golden Reference-аналогам;
   дублирование вместо переиспользования.
6. **Границы и последствия:** влияние на импортёров, конфиги, обратную совместимость API.

Для data-only задач оси 3 и 1 главные, сборка/тесты могут быть пропущены по типу задачи.

## Процедура

1. Прочитай карточку и постановку; составь чек-лист ревью — декомпозиция проверки по
   направлениям рубрики; существенные направления помечай обязательными. Веди чек-лист
   через контракт отчёта (checklist_updates, kind=reviewer).
2. Пройди дифф файл за файлом; выполнение направлений чек-листа отмечай сразу.
3. Перед вердиктом APPROVED все обязательные пункты твоего чек-листа закрыты.
4. Вердикт: APPROVED — блокирующих находок нет; CHANGES_REQUESTED — есть blocking;
   BLOCKED — продолжение бессмысленно до вмешательства человека.
5. Отчёт: находки по рубрике (файл:строка, существенность, «как чинить»); отдельно blocking
   и advisory (nit — только advisory, без отдельных шагов доработки). Комментарий к задаче
   от первого лица: сколько blocking/advisory и с чего начать чинить. Шаги доработки в план
   исполнителя не вносишь — их переосмысливает сам исполнитель.
