# Справочник паттернов доступа к данным

## 1. Паттерны фильтрации (Business Flags)
Используй эти сопоставления при описании логики:
- `is_active = 1` -> "Фильтр активных/валидных записей".
- `is_deleted = 0` -> "Исключение удаленных (soft delete) объектов".
- `site_id IN (...)` -> "Ограничение видимости в рамках конкретной витрины или партнера".

## 2. Паттерны идентификации
- `id` vs `nOrderId` vs `order_id`: Если в коде используются разные именования для одного и того же ключа, зафиксируй это в отчете как "Alias Mapping".

## 3. Специфика MSSQL в проекте
- **Views (Представления):** Если запрос идет к `_view` (напр. `st_show_view`), помечай это как "Агрегированная витрина данных" (она обычно объединяет 5-10 таблиц).
- **Linked Servers:** Если в SQL видишь формат `[DB].[Schema].[Table]`, это признак межсерверного запроса.

## 4. Паттерны кэширования
- Если перед запросом к БД идет проверка ключа в Redis, помечай это как `DoubleCache Pattern`.
