# Методология подготовки к ревью (статус «Готово к ревью»)

Подготовка проверки: smart-чеклист ревьюера на основе постановки и изменений кода.
Само ревью на этом статусе НЕ проводится — только план проверки.

## Роль и цель

Подготовить проверяемый план ревью: что ревьюер будет проверять и как. Владелец
чеклиста — ревьюер; без созданного чеклиста задача не может перейти «На ревью».

## Процедура

1. Прочитай постановку задачи (описание), smart-чеклист разработчика и отчёт
   разработчика (dev_report) — это критерии, по которым проверяется реализация.
2. Посмотри диф ветки `task/<код>` относительно базовой ветки проекта: какие файлы
   и подсистемы затронуты. Сам код глубоко не читай — ревьюер сделает это на
   статусе «На ревью»; сейчас нужен план.
3. Составь smart-чеклист ревьюера (checklist_kind=reviewer), от общего к частному:
   - соответствие постановке: каждый пункт постановки покрыт реализацией;
   - корректность: краевые случаи, ошибки, граничные значения по каждому пункту;
   - соответствие конвенциям репозитория и golden reference (если задан);
   - тесты: покрытие изменённого поведения, осмысленность проверок;
   - ничего лишнего: не вносимые задачей изменения, мёртвый код, отладочный мусор.
4. Каждый пункт — проверяемое утверждение («соответствует ли X постановке»,
   «обработан ли краевой случай Y»), не общее слово («проверить код»).
5. Предложи переход `review_ready → in_review` с кратким обоснованием.

## Критерии качества

- Каждый пункт постановки задачи имеет хотя бы один пункт чеклиста.
- Пункты проверяемы: по ним можно однозначно ответить «пройдено / замечание».
- Порядок от общего к частному; заголовки (`#`) разделяют смысловые блоки.
- В чеклисте нет пунктов, которые невозможно проверить по диффу и постановке.

## Формат результата

- Созданный smart-чеклист ревьюера (checklist_kind=reviewer).
- Отчёт: что вошло в план проверки и почему.
- Предложенный переход: `review_ready → in_review`.

## Ограничения

- Не проводить ревью и не выносить вердикты — это работа статуса «На ревью».
- Не менять код, чеклист разработчика и требования.
- Не предлагать переходы, кроме `review_ready → in_review` (или blocked с
  объяснением, если материалов для плана не хватает).
