---

## Использование

```
/discovery-brief [путь к досье]
```

**Параметры:**

- `[путь к досье]` — опционально; если нет — берётся последнее изменённое `sa_documentation/FNR/FNR_*/`.

## Примеры

```
/discovery-brief
```

```
/discovery-brief sa_documentation/FNR/FNR_5
```

## Важно

**Приоритет:** соблюдение `discovery-analyst/SKILL.md` и `resources/two_layer_language.md`. Брифинг — **только бизнес**, без идентификаторов/классов/флагов.

**Ожидаемый результат:** перегенерированный `03_brief.md` (шаблон `ideal_brief.md`) в досье.

**Запрещено:** писать или править `sa_documentation/tasks.md`; менять `01_decision_backlog.md` (брифинг — проекция, не источник).

## Инструкция для LLM

### Этап 1: Загрузка роли и определение досье

1. Прочитай `discovery-analyst/SKILL.md` и `resources/two_layer_language.md`.
2. Определи досье (указанный путь или последнее изменённое `FNR_<N>/`).

### Этап 2: Чтение состояния

1. Прочитай `01_decision_backlog.md` (источник проекции) и при необходимости `02_answers.md` (чтобы отразить уже решённое).
2. Шаблон — `ideal_brief.md`.

### Этап 3: Пересборка брифинга

1. Сформируй топ-3 (по приоритету) ещё открытых вопросов для руководства — на языке бизнеса.
2. Убери закрытые (🟢) развилки из «Что нужно от вас» (или кратко упомяни как «решено»).
3. Рекомендации и «Что будет, если решить наугад» — на языке бизнеса, по текущему бэклогу.

### Этап 4: Самопроверка

- Тест «понял бы руководитель без кода?» — для каждого предложения.
- В `03_brief.md` нет `<>`, `_`, имён файлов, английских технических терминов.
- `tasks.md` **не тронут**.

### Этап 5: Завершение

Выведи путь к `03_brief.md` и число оставшихся открытых вопросов для руководства.
