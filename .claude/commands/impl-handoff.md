## Использование

```
/impl-handoff <путь к system_requirements> [workspaces.yaml] [strict-mode]
```

**Параметры:**

- `<путь к system_requirements>` — файл СТ (например, `sa_documentation/FNR/FNR_8/system_requirements_concept_f.md`).
- `[workspaces.yaml]` — реестр систем; по умолчанию ищется вверх от каталога СТ и в корне воркспейса.
- `[strict-mode]` — только шлюз готовности СТ: результат в `handoff_report.md`, план не строится.

## Примеры

```
/impl-handoff sa_documentation/FNR/FNR_8/system_requirements_concept_f.md
```

```
/impl-handoff ../other-workspace/sa_documentation/FNR/FNR_3/system_requirements_b.md strict-mode
```

## Важно

**Это входная точка автономного конвейера v3** (канон: `sa_documentation/harness/handoff_pipeline_design.md` §3.7).
/impl-plan строит план и останавливается на шлюзе утверждения; /impl-handoff делает то же плюс
готовит манифест к автономному ведению демоном (поля конвейера v3: pipeline, auto_mode). После
утверждения плана конвейер сам ведёт DAG: реализация → ревью → доработка → следующая задача.
Ручными остаются ровно два шлюза: утверждение плана и приёмка PR.

**Приоритет: шлюз готовности СТ — машиночитаемый.** Любой пробел входа = gap-report + STOP,
артефакты плана не создаются. План строится только из СТ и кода — никаких выдуманных требований.

**Универсальность:** команда не привязана к стеку, БД или домену. Системы и команды гейтов — из
`workspaces.yaml`; знания о подъёме — из `build_info/<система>.md` (если есть); пресеты —
`harness/presets/`. Инструмент `python3` (Windows Git Bash: `python`).

## Инструкция для LLM

Ты — инженер контура реализации (роль: `.claude/skills/impl-harness/SKILL.md`). Задача шага —
принять утверждённые СТ в конвейер: проверить вход, построить план, подготовить манифест v3
к автономному ведению демоном.

### Графовый контекст (complement-модель)

Граф дополняет repomix и живой код, а не заменяет их — как в /impl-plan: если MCP-инструменты
`sa-helper-graph` доступны — используй для структурного среза и impact-анализа; недоступны —
работай через `sa_documentation/<сервис>-docs/repomix-output.xml` и ripgrep по коду.

### Этап 1: Шлюз готовности СТ (машиночитаемый)

1. Прочитай СТ целиком. Прогони чек-лист готовности (результат каждой проверки — pass/fail
   с указанием раздела СТ):
   - каждая задача СТ имеет `| FR-ID | FR-<NN> |` в метаданных задачи;
   - критерии приёмки имеют префиксы `AC-<N.M.k>`;
   - при 2+ системах есть раздел «Затронутые системы и контракты» (система / репозиторий /
     тип изменения / точки интеграции);
   - каждая система из этого раздела есть в `workspaces.yaml` с `bootstrap: ready*`;
   - критерии приёмки проверяемы тестом: нет формулировок «согласовать», «по согласованию»
     без проверяемого механизма.
2. Результат шлюза запиши в `handoff_report.md` (рядом с будущим каталогом `harness/`):
   чек-лист с pass/fail, перечень пробелов, решение (proceed / stop).
3. Есть fail → gap-report и STOP: «исправьте СТ по gap-report, затем повторите /impl-handoff».
   Никаких dossier/tasks/manifest создавать нельзя.
4. Всё pass → продолжай. В strict-mode на этом команда завершается.

### Этап 2: План работ (по канону /impl-plan)

1. Прочитай `.claude/commands/impl-plan.md` и выполни её этапы 2–6 с этим СТ (этап 1 — шлюз
   пробелов — уже сделан выше, не дублируй): `story-init --status-planned` → досье/план
   (doc-set) → task-create → card-set → comment-add → validate → story-status
   AWAITING_APPROVAL.
2. Отличия от /impl-plan только два:
   - Story получает поля конвейера v3: `sahelper story-set FNR --auto-mode 1
     --auto-review-strategy closure_first` (владелец поля — impl-handoff);
   - в execution_plan добавь раздел «Автономный прогон»: как конвейер поведёт задачи
     (порядок DAG, где человек увидит паузы/эскалации), команда запуска демона.

### Этап 3: Журнал и завершение

1. `sahelper comment-add FNR <T<k>> --author agent --text "СТ передана в конвейер
   (/impl-handoff): <N> задач, DAG <кратко>. План ждёт утверждения"` — в каждую задачу.
2. Выведи FNR и литеральную подсказку:

«СТ передана в конвейер. Следующие шаги: 1) утвердите план — кнопка «✓ План» в витрине
(или `sahelper flag FNR APPROVE_PLAN`); 2) запустите конвейер: `python3 harness/orchestrator.py
--workspace <корень воркспейса>` — конвейер сам проведёт задачи по DAG до PR-заготовок;
управление — в витрине (http://127.0.0.1:4040)».
