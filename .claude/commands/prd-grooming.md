## Использование

```
/prd-grooming <PRD или ссылка на него>
```

**Параметры:**

- `<PRD>` — текст PRD, вставленный в запрос, либо ссылка/путь на документ (Confluence, `.md`, `.html`). Можно приложить ссылку на макеты — тогда проверяется согласованность PRD ↔ дизайн.

## Примеры

```
/prd-grooming <вставленный текст PRD «Интеграция Кино во флоу TL»>
```

```
/prd-grooming https://confluence.mts.ru/pages/viewpage.action?pageId=2300579320
Макеты: https://www.figma.com/design/....
```

```
/prd-grooming sa_documentation/prd/source/kino.html
```

## Важно

**Приоритет:** СТРОГОЕ соблюдение роли и принципов из `SKILL.md` и структуры отчёта из `examples/ideal_grooming_report.md`.

**Ожидаемый результат:** Файл `sa_documentation/prd/{file_name}.md` с отчётом о груминге (комментарии, замечания, вопросы). `{file_name}` — kebab-case слаг из заголовка PRD с суффиксом `-grooming` (напр. `kino-integration-grooming.md`). Если заголовок не извлекается — спроси имя или используй `prd-grooming-<N>.md`.

**Груминг ≠ переписывание.** Команда не создаёт БФТ/СТ и не проектирует решение — только диагностирует документ. Превращение в БФТ — отдельный шаг после груминга.

**Универсальность:** Команда не привязана к конкретному стеку, БД или бизнес-домену.

## Инструкция для LLM

### Графовый контекст (complement-модель)

Ось «реализуемость» подтверждается кодом, если PRD касается систем в кодовой базе. Используй оба источника одновременно:
- **repomix-output.xml** — полный текст кода (реализации, SQL, комментарии);
- **MCP-инструменты** (если sa-helper-graph подключён): `graph_introspect` (реальные метки перед запросами), `graph_schema` (обзор структуры), `graph_impact` (зависимости компонента), `graph_call_chain` (трассировка).

Если система внешняя/сторонняя или MCP недоступен — не выдумывай реализуемость, фиксируй её как вопрос к команде/архитектору.

### Этап 1: Загрузка роли

1. Прочитай `/prd-groomer/SKILL.md` — твоя персона и принципы.
2. Загрузи шаблон из `examples/ideal_grooming_report.md`.
3. Загрузи чек-лист из `resources/grooming_checklist.md`.

### Этап 2: Получение PRD

1. Если PRD вставлен текстом — работай с ним.
2. Если дана ссылка/путь — прочитай (WebFetch для URL, Read для файла). Если недоступно — попроси вставить текст.
3. Если приложены макеты — учти их для оси непротиворечивости (PRD ↔ дизайн). Если только PRD — расхождения с дизайном фиксируй как вопросы.

### Этап 3: Сбор контекста проекта (для оси реализуемости)

1. Проверь `sa_documentation/repomix-output.xml` — если есть, используй как источник кода; если нет — предупреди, что ось реализуемости опирается на вопросы, а не на код-доказательства.
2. Прочитай релевантные артефакты `sa_documentation/` (naming_conventions.md, существующие БФТ/СТ) — не дублируй, ссылайся.
3. Живой код и граф — только для подтверждения/опровержения конкретных заявлений о реализуемости.

### Этап 4: Проход по осям

Пройди PRD четыре раза по методологии `SKILL.md` (Шаг 2), по одной оси за проход:
1. Понятность — проверяемость критериев, термины, атомарность, «резиновые» формулировки.
2. Валидность — трассировка на цели/сценарии, измеримость метрик (база/цель/срок), scope, негативные сценарии.
3. Реализуемость — источники данных под поля/фильтры/признаки, поддержка платформой, внешние зависимости, деградация; где можешь — код-доказательства.
4. Непротиворечивость — разделы между собой, текст ↔ макеты, перекрёстные ссылки.

Для каждой находки фиксируй: ось, severity (🔴/🟠/🟡), опору (раздел / код / макет / «вопрос»), суть, почему проблема, рекомендацию, вопрос+адресата.

### Этап 5: Консолидация и вердикт

1. Убери дубли, объедини близкие находки, системные наблюдения вынеси в резюме.
2. Заполни сводку находок и сводную таблицу вопросов (каждый вопрос — с адресатом).
3. Сформулируй вердикт: 🔴 Не готов (есть блокер) / ⚠️ Условно готов / ✅ Готов. Вердикт обязан быть согласован с находками.

### Этап 6: Формирование отчёта

1. Если `sa_documentation/prd/` не существует — создай.
2. Определи `{file_name}` (kebab-case слаг заголовка PRD + `-grooming`). Если файл уже есть — не затирай молча: спроси или добавь суффикс версии.
3. Создай `sa_documentation/prd/{file_name}.md` по шаблону `ideal_grooming_report.md`.
4. Прогони отчёт по `resources/grooming_checklist.md`, закрой Hard Gates.

### Этап 7: Завершение

Выведи: «Груминг PRD завершён: `sa_documentation/prd/{file_name}.md`. Вердикт: <…>. Блокеров: <N>, существенных: <N>, уточнений: <N>.» Кратко перечисли 🔴-блокеры. При желании предложи следующий шаг — сборку БФТ на основе PRD и находок.
